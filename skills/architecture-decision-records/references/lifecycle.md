# Decision lifecycle and review cases

| Event | Record action |
|---|---|
| Considering an option | Proposed draft; no claim that it governs the project |
| Authorized choice | Accepted record with actual deciders and decision date |
| Choice no longer applies | Deprecated status with reason; preserve history |
| New choice replaces old | New record names its predecessor; old record names replacement |
| Recording a past choice | Separate decision/recording dates and flag missing history |
| Two writers choose the same number | Exclusive creation rejects collision; allocate another ID |
| Existing custom decision folder | Preserve its naming, index and status conventions |

For a supersession, check both records and the index agree. The replacement's
status must be truthful: a proposed replacement does not automatically supersede
an accepted decision. If the replacement is rejected, the original remains active.

Useful probes: explicit "record this" causes the authorized write without
reconfirmation; "why X?" produces a cited read-only answer; unknown rationale
stays unknown; a filename collision preserves both authors' content. Verify
actual file changes, not an agent's statement that it wrote a record.
