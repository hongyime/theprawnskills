# Skill review report

Lead with the assessment: ready, ready with stated limitations, or fixes required.
State the reviewed commit or working-tree scope and the checks actually performed.

For each finding, provide:

- Severity and short problem statement.
- File and line; the input or action that exposes the issue.
- Evidence, consequence, and a specific correction.

Then list validation results, including failures and skipped checks. Identify
external prerequisites separately from missing bundled files. Mention useful
strengths only when supported by the review; do not pad the report to a quota.

A compact result can use a table of severity, location, finding, and fix. Close
with any unresolved blockers. Report zero findings only within the reviewed scope,
never as a guarantee that every skill or provider integration works.
