Visual overview

The same three moves work for a short explanation, an architecture decision, or a longer review.

  1. Understand

    Find the question.

    What relationship, choice, or behavior needs to become clear?

  2. Make visible

    Draw the explanation.

    Choose a flow, sequence, architecture view, or evidence-based chart.

  3. Make useful

    Give the next step.

    Connect the visual to a decision, an action, or a useful check.

A small question gets a small document. The structure stays familiar; the subject determines the visual.

02

Details

Consistency makes room for the idea.

The palette, type, spacing, and document order stay stable. A user flow explains choices. A sequence explains messages. A C4 view explains system boundaries. The right diagram depends on the question.

Use a visual when it removes work for the reader—even when the answer is short.

Tables still belong here when comparing properties. They should support the explanation instead of becoming the only way every subject is presented.

What stays the same?

A restrained dark background, one cyan accent, readable system fonts, and the overview → details → next steps structure.

What changes with the subject?

The diagram type, depth, evidence, and useful interaction. A brief explanation can fit in one screen; a larger report can reveal supporting detail progressively.

Does this need a connection to display?

No. The CSS, diagrams, and small view switcher are inline. With JavaScript disabled, both diagram views remain available. Hosting is a separate delivery choice.
